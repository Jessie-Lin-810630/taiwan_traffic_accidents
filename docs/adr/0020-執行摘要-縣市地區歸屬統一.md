## 一、病因定義

「這個縣市屬於哪個地區」在四支腳本各寫一份，四份的分法互不相同。宜蘭縣在
`e_crawling_nightmarket` 是東部、在 `v_act1_all_accident` 是東部與東部離島、
在 `v_act1_city_accident.region_map` 是北部。澎金馬那一組在三份叫「離島」、
在一份叫「其他離島」。

由此產生的兩個問題，病因的完整論證見
[ADR-0020 背景章節](./0020-縣市地區歸屬統一為單一原則.md#背景)：

1. 同一個宜蘭夜市在全臺頁與縣市頁被歸到不同地區，兩頁的地區統計對不起來
2. 全臺頁的 radio 選項寫「離島」而字典鍵是「其他離島」，
   `get_region_or_cities()` 走到 `.get(region, "")` 回傳空字串，
   熱力圖靜默空白且不報錯

附屬離島的處理另有一層問題。琉球鄉在屏東縣、蘭嶼鄉與綠島鄉在臺東縣，
縣市層級的查表抓不到它們，所以另外用關鍵字覆寫。改動前的三處覆寫
一律把這三個離島歸到「東部與東部離島」，其中琉球在地理上並不屬於東部。

## 二、決策摘要

[ADR-0020 的三項決策](./0020-縣市地區歸屬統一為單一原則.md#決策)逐條落實：
五個地區的定義（宜蘭縣歸北部、離島短名為「其他離島」）、附屬離島的覆寫拆成
琉球與蘭嶼綠島兩組、不動 mart 層以經緯度切分的事故分區。

## 三、實際改動

### 3.1 四份對照表的內容對齊

| 檔案 | 改動前 | 改動後 |
| --- | --- | --- |
| `e_crawling_nightmarket.cities_per_region` | 宜蘭在東部，五區名為北中南東離島 | 宜蘭在北部，五區名依決策一 |
| `v_act1_all_accident.cities_per_region` | 宜蘭在東部與東部離島 | 宜蘭在北部 |
| `v_act1_all_accident` 的 radio 選項 | `"離島"`，與字典鍵對不上 | `"其他離島"`，與字典鍵一致 |
| `v_act1_city_accident.region_map` | 澎金馬為「離島」 | 澎金馬為「其他離島」 |
| `v_act1_city_accident.REGION_ORDER` | 「離島」 | 「其他離島」 |

第三列同時解掉病因第 2 點：radio 送進 `get_region_or_cities()` 的字串現在查得到，
選「其他離島」會正常篩出澎湖、金門、連江與琉球。

### 3.2 附屬離島的覆寫拆成兩組

`c_data_service.get_all_nightmarkets()` 與 `v_act1_city_accident.get_real_city_data()`
兩處都改成同一個迴圈：

```python
for keyword, region in (("琉球", "其他離島"), ("蘭嶼|綠島", "東部與東部離島")):
```

兩處的元組內容一字不差，日後若有一邊被單獨改動，比對即可看出。

三個離島的實際結果：琉球從「東部與東部離島」改成「其他離島」，這是唯一改變結果的一筆；
蘭嶼與綠島在臺東縣，縣市層級已是「東部與東部離島」，覆寫前後同值。

### 3.3 一處對決策文的偏離

**ADR 的預計改動清單少列了三處 docstring。** 決策文只列了程式碼與測試，
實作時發現三支函式的 docstring 寫著舊的地區名或舊的離島歸屬，一併改掉：

| 位置 | 原本寫的 |
| --- | --- |
| `e_crawling_nightmarket.find_tw_night_markets_list()` | 「標上北部、中部、南部、東部或離島」 |
| `c_data_service.get_all_nightmarkets()` | 「含琉球、蘭嶼、綠島的夜市歸到東部與東部離島」，範例列的小琉球夜市也是 |
| `v_act1_city_accident.get_real_city_data()` | 同上 |

### 3.4 DDL 註解

`create_night_markets_tables.py` 的 `region` 欄 COMMENT 原本寫
「夜市所屬地區(北、中、南部)」，只列三個，補成五個。欄位型別
`VARCHAR(10)` 不變，「其他離島」與「東部與東部離島」都在長度內。

### 3.5 測試

全檔 319 支，本輪動了三處：

| 測試 | 釘住的決策 |
| --- | --- |
| `test_地區由縣市反查而不是另外比對` | 臺東縣的期望值由「東部」改為「東部與東部離島」 |
| `test_宜蘭縣屬北部`（新增） | 決策一：宜蘭縣的歸屬，抓取階段寫進 MySQL 的就是這個值 |
| `test_琉球的夜市歸到其他離島`（由原參數化拆出） | 決策二：琉球那一組 |
| `test_蘭嶼與綠島的夜市歸到東部與東部離島` | 決策二：蘭嶼綠島那一組 |

原本是一個參數化涵蓋六個案例、共用一句斷言。琉球改歸屬後那句斷言只能二選一，
所以拆成兩個參數化各自斷言，日後任一邊被改動會單獨紅一個測試。

### 3.6 同一波順帶完成的其他改動

`c_data_service.aggregate_national_master()` 的 docstring 與三處註解由使用者
自行改寫，內容是把聚合流程講得更具體。與本輪的地區歸屬無關，因為在同一個檔案裡，
一併進 commit。
