## 一、病因定義

事故 pipeline 的同一個 task 內，讀與寫的目標資料庫由兩個不同的來源決定：
`t_fact_accident_*()` 把 `"traffic_accidents"` 寫死在函式內（三支合計 8 處），
`l_fact_accident_*()` 則收 DAG 從 `os.getenv("MYSQL_DATABASE")` 取來的值。

兩者一致時看不出問題。`MYSQL_DATABASE` 一旦指向別的資料庫，`t_` 仍會去讀
`traffic_accidents` 的維度表，取回來的外鍵被寫進另一個資料庫的事實表。

同時，`os.getenv("MYSQL_DATABASE")` 回傳的 `None` 一路傳到底都沒有人擋。

病因的完整論證見
[ADR-0018 背景章](./0018-事故轉換階段的資料庫名稱由呼叫端傳入.md#背景)。

## 二、決策摘要

[ADR-0018 的四項子決策](./0018-事故轉換階段的資料庫名稱由呼叫端傳入.md#四項子決策)，
逐條落地：三支 `t_` 新增 `database` 參數、型別為必填的
`str`、DAG 在取得環境變數的當下驗證、本輪只改 `d02` 與 `d03` 兩支 DAG。

## 三、實際改動

### 3.1 三支 `t_fact_accident_*()` 的參數與 docstring

- `csvfile_paths` 之後新增 `database: str`，函式內 8 處 `database="traffic_accidents"`
全部改為 `database=database`：

| 檔案 | 改掉幾處 | 查的是什麼 |
| --- | --- | --- |
| `t_fact_accident_env.py` | 4 | `dim_accident_day`、`dim_road_design`、`dim_lane_design`、`fact_accident_main` |
| `t_fact_accident_main.py` | 2 | `dim_accident_day`、`dim_accident_type` |
| `t_fact_accident_human.py` | 2 | `dim_accident_day`、`fact_accident_main` |

- 改完後這三支不再出現任何資料庫名稱字面值。清洗步驟、主鍵演算法、去重與排序
的依據都沒有動。

- 三支函式 docstring 的 `Args` 補上 `database`。`Notes` 各補一句
「資料庫名稱由呼叫端傳入參考 ADR-0018」。

### 3.2 兩支 DAG 的呼叫端與缺值檢查

- `d02` 的三處呼叫（`task_t_and_l_fact_main` 一處、`task_t_and_l_other_facts` 兩處）
與 `d03` 的三處呼叫全部補上 `database`。`d03` 的
`task_t_and_l_other_facts` 走 dynamic task mapping，`database` 原本就從
`partial()` 傳入，`expand()` 則不需改。

- 兩支 DAG 在取得環境變數之後立即檢查：

```python
database = os.getenv("MYSQL_DATABASE")
if not database:
    raise ValueError("未設定 MYSQL_DATABASE，請檢查環境變數設置")
```

- **實作期的兩個決定，ADR 沒有寫到：**
  - 用 `if not database` 而不是 `is None`。空字串同樣不是有效的資料庫名稱，
    `not` 兩者都擋。
  - 訊息格式參照 `mysql_utils._require_credentials()` 的句型設計，
    見 [ADR-0008 決策章](./0008-必填設定在使用時驗證.md#決策)。

### 3.3 測試

- **既有測試的呼叫點 5 處**（`test_util_read_traffic_accident_file.py` 4 處、
`test_task_t_fact_main_pk_stability.py` 1 處）補上資料庫名稱。其中 `Test空輸入::test_空_pathlist_六支一律_raise` 的參數化涵蓋六支 `t_`，而 dim 三支不查資料庫、簽名沒有變。新增一個 `TRANSFORMS_NEEDING_DATABASE` 集合分流呼叫引數，`TRANSFORMS` 本身不動。

- **新增 `Test資料庫名稱由呼叫端決定`**，參數化跑 fact 三支，釘住「傳進來的名稱會原樣送到 `get_table_from_sqlserver`」。作法是把查詢函式換成 `side_effect=RuntimeError`，讓它停在第一次查詢，然後斷言
`call_args.kwargs["database"]`：

```python
with patch.object(
    module, "get_table_from_sqlserver", side_effect=RuntimeError("停在第一次查詢")
) as mock_query:
    with pytest.raises(RuntimeError):
        getattr(module, module_name)([str(path)], TEST_DATABASE)

assert mock_query.call_args.kwargs["database"] == TEST_DATABASE
```

不把 transform 跑完，是為了避免替三支各複製一整組假維度表，要證明的只是
「名稱有傳到」。


### 3.4 順便修的一處：`find_download_links()` 的 `page_topic`

- 不屬於
  [ADR-0018 的範圍](./0018-事故轉換階段的資料庫名稱由呼叫端傳入.md#未納入本次範圍)，
  是同一工作時間順手修的。
  - `find_download_links()` 原本用一個 CSS selector 從 data.gov.tw 的頁面上取下載檔的檔名，選不到時 `page_topic` 保持 `None`，而且**不留任何紀錄**。但這個 `None` 會被放進回傳的 dict，一路帶到 `e_crawling_historical_traffic_accident()` 組 ZIP 檔名的地方。

- 本輪加了兩件小修改：
  - **page_topic 為 `None` 時記一筆 warning**，並把 `url` 帶進訊息，看日誌就知道是哪一頁。
    歸類為 warning 而非 error，是因為抓取本身沒有失敗，只是檔名取不到。
  - 組檔名處補 `page_topic or "Untitled"` 作為 fallback，讓抓取繼續走完。
