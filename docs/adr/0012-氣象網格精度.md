- 來源：[ADR-0011 執行摘要](./0011-執行摘要-天氣-etl-併入既有存取介面.md)候選 3 的討論過程

## 名詞

| 詞 | 意思 |
| --- | --- |
| **氣象網格** | OpenMeteo 背後的天氣模式把地表切成的格子。同一格內的所有座標拿到的是同一份觀測值 |
| **進位** | 把事故的經緯度對到網格上，讓落在同一格的事故共用一次 API 請求 |
| **高程降尺度** | OpenMeteo 依座標的海拔調整氣溫的機制 |

## 背景

事故經緯度目前進位到小數點後兩位（0.01 度，約 1.1 公里），一年得到
**11,000 個相異座標**。以 50 個座標為一批，一年 220 個批次。

OpenMeteo 免費層的呼叫次數是加權計算的 —— 一次請求涵蓋的地點數、天數、
變數數愈多，計入的次數愈多。本 pipeline 一批要 50 個地點、整年逐小時、
7 個變數，因此很快就會用盡每日額度。實務上跑不完一年份。

### 0.01 度比模式網格細得多

實測 OpenMeteo archive API（2024 年資料）：

```
請求緯度 24.11  ->  網格中心 (24.147627, 120.605736)  氣溫 15.9
請求緯度 24.13  ->  網格中心 (24.147627, 120.605736)  氣溫 15.9
請求緯度 24.15  ->  網格中心 (24.147627, 120.605736)  氣溫 15.9
```

相鄰網格中心的緯度間距是 **0.0703 度**（約 7.8 公里，2017 年起的資料
來自 ECMWF IFS 9km）。0.01 度的間距遠比它細，所以多數相鄰座標拿回的是
**完全相同的資料**，卻各自消耗一份額度。

以 400 個 0.01 度座標實測，只對應 **15 種相異的天氣序列**。

### 但預設的高程降尺度會讓進位失去意義

OpenMeteo 預設以 90 公尺解析度的數值地形模型查出每個座標的海拔，
再據此調整氣溫（[官方文件](https://open-meteo.com/en/docs/historical-weather-api)）。
於是同一個網格內的座標，會因為海拔不同而拿到不同的氣溫，
連帶影響 API 選擇的網格 —— 進位後的去重結果因此無法預測。

實測同一批座標：不指定高程時落在 2 個網格，指定固定高程時收斂成 1 個。

## 決策

### 一、事故經緯度進位到 0.05 度

`GRID_STEP = 0.05`。

0.05 度**仍比模式網格的 0.0703 度細**，所以不會把兩個原本不同的網格併成一個；
差異只發生在網格邊界。實測 400 個座標進位後剩 25 個，請求數降到 6%。

推估一年的 11,000 個座標會降到 700 上下，跑完一年所需的天數從約 29 天
降到 2 天左右。

不選 0.1 度：那已經比模式網格粗，一個進位後的座標會橫跨約兩個網格，
是系統性地把真實差異抹掉，而非邊界效應。

### 二、請求時固定 `elevation=10`

`FIXED_ELEVATION_M = 10`。

台灣的車禍絕大多數發生在人口密集的平地市區，取 10 公尺符合台北、台南、
高雄一帶的實際海拔。**山區道路的氣溫會因此偏高**（每 100 公尺高差約 0.65°C），
這個偏差是主動承擔的：換得的是同一網格內的座標拿到一致的觀測值，
進位與去重才有意義。

### 三、進位的算法收成單一函式

```python
def round_to_weather_grid(series: pd.Series) -> pd.Series:
    scaled = series.astype("float64") / GRID_STEP
    return (scaled.round() * GRID_STEP).round(2)
```

事故資料與天氣資料最後要 merge（`t_dataclr_weather_hist`），兩邊的經緯度
必須用同一支函式算出來。只要有一邊用了別的算法，join 會一列都對不上，
而且不會報錯 —— 與 ADR-0010 要消除的病因同一類。

末尾的 `.round(2)` 是必要的，不是修飾：`24.13 / 0.05` 取整後乘回去，
浮點運算可能得到 `24.150000000000002`，而 hash 是拿字串算的，
多出來的尾數會讓兩邊算出不同的 hash。

## 後果

### 正面

- 一年的請求量降到約 6%，429 從必然發生變成邊界情況
- 進位的算法只有一處，改精度只改一個常數
- 固定高程讓同一網格內的觀測值一致，去重結果可預測

### 負面

- 山區事故的氣溫偏高，海拔 500 公尺處約偏高 3.5°C
- 事故取用的觀測點最遠可能在 2.8 公里外（0.05 度的一半），
  原本是 0.55 公里

### 中性

- `fact_hourly_weather` 的 `longitude_round` / `latitude_round` 仍是
  `DECIMAL(6,2)`，0.05 度的值最多兩位小數，型別不需要改，只需修正欄位註解
- GCS 上尚無任何檔案，因此不存在既有快取失效的問題
